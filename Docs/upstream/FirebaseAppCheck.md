### 13.2.0
- [x] [added] `AppCheckDebugProvider` now automatically uses a debug token provisioned by the Firebase CLI (`firebase appcheck:debugtokens:create`) when running in a Simulator. The token is read for the app's Google App ID from `~/.config/configstore/firebase-appcheck.json` on the host machine, so no manual token registration is needed. The `AppCheckDebugToken` and `FIRAAppCheckDebugToken` environment variables still take priority. ([#17017](https://github.com/firebase/firebase-ios-sdk/pull/17017))
  **Ported**: `AppCheckDebugTokenConfigStore` reads the token in a Simulator and `AppCheckDebugProvider` passes it to AppCheckCore 12.1.0's `debugToken:`. Log IDs I-FAA003004–6 (upstream's I-FAA004003–5; the port numbers the debug provider's messages I-FAA003xxx). Upstream's tests ported; the config store's run on every platform against a temporary home directory.
- [x] [fixed] When the `AppCheckDebugToken` or `FIRAAppCheckDebugToken` environment variable is set, `AppCheckDebugProvider` no longer generates an unused local debug token and logs registration instructions for it. ([#17017](https://github.com/firebase/firebase-ios-sdk/pull/17017))
  **Ported** with AppCheckCore 12.1.0: only the local token is logged and tracked as registered.
