### 13.2.0
- [x] [fixed] Fixed an issue where the `getData` error said that the client was offline when the server rejected the request, e.g. because of security rules. ([#11835](https://github.com/firebase/firebase-ios-sdk/pull/11835))
  **Ported**: the error describes the server's reason; the "client offline" text is kept for a get that timed out waiting for a connection.
- [x] [fixed] Fixed an issue where a completing `getData` call marked an observed or `keepSynced` query inactive in the persistence cache, allowing its cached data to be pruned or triggering an assertion failure on subsequent updates. ([#17009](https://github.com/firebase/firebase-ios-sdk/pull/17009))
  **Ported**: `FRepo.getData` marks the query active and inactive through `FSyncTree.setQueryActive`/`setQueryInactive`, which keeps it active while an observer or keepSynced needs it. Test `testSetQueryInactiveKeepsObservedQueriesActive` (Port note: upstream tests it through FRepo with a mock persistence manager).
- [x] [fixed] Fixed an issue where `getData` on a query with a limit or range could remove data from other listeners at or below the query's location, and from the disk cache. (#8286, #14137)
  **Ported**: `FSyncTree.applyGetResultForQuery` applies a filtered result to the query's own view, through a temporary `FGetResultEventRegistration`. Upstream uses a new `FKeepSyncedEventRegistration`, which matches only itself; here registrations are removed by matcher, so it has its own (`.getResult`). Upstream's `FSyncPointTests` ported; integration tests `aFilteredGet…`.
- [x] [fixed] Fixed an issue where `getData` never completed if the connection dropped before the server responded. ([#16717](https://github.com/firebase/firebase-ios-sdk/pull/16717))
  **Ported, with a timeout**: the port used to fail such gets (P2); now, as upstream, they're marked unsent and resent after a reconnect. Unlike upstream, each gets a new connect timeout (3 s), so a client that stays offline still falls back to the cache. Tests `aSentGetIsResentAfterADrop`, `aSentGetFailsIfTheClientStaysOffline`.
- [x] [fixed] Fixed an issue where `getData` on a child of an observed location returned the data of the observed location instead of the child. ([#12168](https://github.com/firebase/firebase-ios-sdk/pull/12168))
  **Ported**: `FSyncTree.getServerValue` takes the view from the sync point at the query's own path, and no longer leaves an empty sync point in the tree. Integration tests `getDataOfAChildOf…`.
- [x] [fixed] Fixed an issue where the client could stay offline for hours after a connection attempt timed out, for example after the device woke from sleep. ([#9682](https://github.com/firebase/firebase-ios-sdk/pull/9682))
  **Ported for the NIO transports**: the same hang existed. The session's handshake timeout cancels the transport, but the TLS handshake and WebSocket upgrade ignored cancellation; now cancellation closes the channel (`withWebSocket`). Conformance test `cancellationEndsAStalledUpgrade`, which hangs without the fix.
- [x] [fixed] Keep Realtime Database WebSocket keepalive timers and connection state on the worker queue to avoid cross-thread access. (#16767, #16971)
  **Not affected**: the keepalive is a child task of the session, on the Database actor.

#### 13.1.0
- [x] [fixed] Fixed a race where calling childByAutoId() concurrently from multiple threads could generate duplicate push IDs. ([#16768](https://github.com/firebase/firebase-ios-sdk/pull/16768))
  **Ported**: `FNextPushId.get` locks its state. Test `concurrentPushIdsAreUniqueForTheSameTimestamp`.
- [x] [fixed] Fixed an issue where transactions could fail with a maxretry error when every child of a node had a priority. ([#16769](https://github.com/firebase/firebase-ios-sdk/pull/16769))
  **Already fixed**: the port found and fixed the same inverted check in `FNode.dataHash()` independently.
- [x] [fixed] Fixed an issue where observers could miss events, and keep showing stale or reverted values, when multiple pending transactions at overlapping locations were rerun. ([#16791](https://github.com/firebase/firebase-ios-sdk/pull/16791))
  **Not affected**: the port resets its event list to `[]`; upstream's Objective-C set it to `nil`, which dropped later events.
- [x] [fixed] Fixed an issue where a `getData` call that failed without a cached value kept its query marked as active in the persistence cache until the app restarted, which kept that location from being pruned. ([#16792](https://github.com/firebase/firebase-ios-sdk/pull/16792))
  **Not affected**: the port marks the query inactive in a `defer`.
- [x] [fixed] Fixed a potential crash at every launch after the server sent an invalid database host. Such hosts are now ignored, and a saved one is discarded. ([#16863](https://github.com/firebase/firebase-ios-sdk/pull/16863))
  **Ported**: `FRepoInfo.isValidHost(_:)` guards the saved host, server-provided hosts and resets; the connection URL is no longer force-unwrapped. Tests in `FRepoInfoTests`.
- [x] [fixed] Fixed a potential crash when the server sent a data message with an `error`. ([#16863](https://github.com/firebase/firebase-ios-sdk/pull/16863))
  **Ported**: logged instead of `fatalError`.
- [x] [fixed] Fixed a crash in `purgeOutstandingWrites` when the server had already acknowledged a write that the SDK hadn't processed yet. ([#5161](https://github.com/firebase/firebase-ios-sdk/pull/5161))
  **Ported**: `ackUserWriteWithWriteId` ignores acks for removed writes (it hit an `assert` in debug builds).
- [x] [fixed] Fixed a crash in `getData` when the server returned an error without a reason. ([#16718](https://github.com/firebase/firebase-ios-sdk/pull/16718))
  **Ported**: the port didn't crash, but now falls back to the status for the reason, as upstream does.
- [x] [fixed] Ignore malformed realtime server push, control, and handshake messages instead of crashing when a frame or one of its fields has an unexpected JSON type. ([#16750](https://github.com/firebase/firebase-ios-sdk/pull/16750))
