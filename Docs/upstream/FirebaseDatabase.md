## CHANGELOG (`FirebaseDatabase/CHANGELOG.md`)

### 13.1.0
- [x] [fixed] Fixed a race where calling childByAutoId() concurrently from multiple threads could generate duplicate push IDs. ([#16768](https://github.com/firebase/firebase-ios-sdk/pull/16768))
  **Ported**: `FNextPushId.get` locks its state. Test `concurrentPushIdsAreUniqueForTheSameTimestamp`.
- [x] [fixed] Fixed an issue where transactions could fail with a maxretry error when every child of a node had a priority. ([#16769](https://github.com/firebase/firebase-ios-sdk/pull/16769))
  **Already fixed**: the port found and fixed the same inverted check in `FNode.dataHash()` independently.
- [x] [fixed] Fixed an issue where observers could miss events, and keep showing stale or reverted values, when multiple pending transactions at overlapping locations were rerun. ([#16791](https://github.com/firebase/firebase-ios-sdk/pull/16791))
  **Not affected**: the port resets its event list to `[]`; upstream's Objective-C set it to `nil`, which dropped later events.
- [x] [fixed] Fixed an issue where a `getData` call that failed without a cached value kept its query marked as active in the persistence cache until the app restarted, which kept that location from being pruned. ([#16792](https://github.com/firebase/firebase-ios-sdk/pull/16792))
  **Not affected**: the port marks the query inactive in a `defer`.
- [x] [fixed] Fixed a potential crash at every launch after the server sent an invalid database host. Such hosts are now ignored, and a saved one is discarded. ([#16863](https://github.com/firebase/firebase-ios-sdk/pull/16863))
  **Ported**: `FRepoInfo.isValidHost(_:)` guards the saved host, server-provided hosts and resets; the connection URL is no longer force-unwrapped. Tests in `FRepoInfoTests`.
- [x] [fixed] Fixed a potential crash when the server sent a data message with an `error`. ([#16863](https://github.com/firebase/firebase-ios-sdk/pull/16863))
  **Ported**: logged instead of `fatalError`.
- [x] [fixed] Fixed a crash in `purgeOutstandingWrites` when the server had already acknowledged a write that the SDK hadn't processed yet. ([#5161](https://github.com/firebase/firebase-ios-sdk/pull/5161))
  **Ported**: `ackUserWriteWithWriteId` ignores acks for removed writes (it hit an `assert` in debug builds).
- [x] [fixed] Fixed a crash in `getData` when the server returned an error without a reason. ([#16718](https://github.com/firebase/firebase-ios-sdk/pull/16718))
  **Ported**: the port didn't crash, but now falls back to the status for the reason, as upstream does.
- [x] [fixed] Ignore malformed realtime server push, control, and handshake messages instead of crashing when a frame or one of its fields has an unexpected JSON type. ([#16750](https://github.com/firebase/firebase-ios-sdk/pull/16750))
  **Not affected**: the port reads server messages with checked casts throughout.

### 12.19.0
- [x] [fixed] Reconnect after significant system clock changes so that `.info/serverTimeOffset` is refreshed. ([#363](https://github.com/firebase/firebase-ios-sdk/pull/363))
  **Ported** on Apple platforms (`NSSystemClockDidChange` isn't posted on Linux).

### 12.17.0
- [x] [fixed] Fixed an issue where surrogate pair replacement ranges were incorrect in push ID generation. ([#16415](https://github.com/firebase/firebase-ios-sdk/pull/16415))
  **Ported**, along with the rest of upstream's general `successor`/`predecessor`: the port had an older, push-ID-only version that hit `fatalError` for keys with other characters, e.g. `queryStarting(afterValue: "a b")`. Upstream's tests ported in `FNextPushIdTests`. Upstream's successor falls through from the `0xD800` case and changes the preceding character; the port doesn't (test `successorEnteringTheSurrogateRangeKeepsThePrefix`).
- [x] [fixed] Fixed a potential crash when receiving non-text WebSocket frames. ([#16414](https://github.com/firebase/firebase-ios-sdk/pull/16414))
  **Not affected**: `WebSocketClient` ignores binary frames.

### 12.7.0
- [x] [fixed] Fix `Fatal Exception: FirebaseDatabasePersistenceFailure`. ([#4493](https://github.com/firebase/firebase-ios-sdk/pull/4493))
  **Ported**: a failure to exclude the folder from backups is logged instead of crashing, and the folder gets the `completeUntilFirstUserAuthentication` protection on Apple platforms.
- [x] [fixed] Concurrency crash in FView. ([#15514](https://github.com/firebase/firebase-ios-sdk/pull/15514))
  **Not affected**: `FView` is only used from the database actor.

### 11.9.0

Note that this may expose a Thread Performance Checker Warning ([#12883](https://github.com/firebase/firebase-ios-sdk/pull/12883)). (#14188, #13877, #13855, #13529)
  **Not applicable**: the port uses its own NIO WebSocket client.
- [x] [fixed] Added `Sendable` conformance to `DataSnapshot` ([#14369](https://github.com/firebase/firebase-ios-sdk/pull/14369)).
  **Already done**: `DataSnapshot` is a `Sendable` struct.
