# Upstream baselines

Which [firebase-ios-sdk](https://github.com/firebase/firebase-ios-sdk) release
each module was ported from, so upstream fixes since then can be found and
ported. The table is generated by comparing every module with the same paths in
each upstream release:

```sh
scripts/upstream/baselines.py --write UPSTREAM.md   # add --files for a per-file breakdown
```

The script keeps a blobless clone of firebase-ios-sdk in
`~/.cache/firebase-swift` and only fetches the file versions it compares.

- **exact** modules are vendored: files are compared by git blob ID, and the
  score is the share of identical files.
- **lines** modules are Swift ported to Swift: matching files are compared line
  by line, ignoring comments, blank lines and indentation. The port rewrote a
  lot, so scores are well below 1; what matters is which release scores
  highest.
- **strings** modules are Objective-C ported to Swift: matching files are
  compared by their string literals (log codes, error messages, wire
  constants), the part that survives a change of language.

*Synced to* is the agreed baseline: everything upstream up to that release is
ported or deliberately left out. It's set by hand in
`scripts/upstream/upstream.py`, from the analysis below, and raised after each
sync. *Closest releases* is what the comparison finds; releases that score the
same have identical upstream files.

## Reading the results

**Firestore: synced to 13.1.1.** It was ported from 12.19.2 and synced by
applying the upstream diff. The C++ core, protos and Objective-C API match
13.1.1 file for file, apart from the changes the port needs: four Apple
`.mm` files in `core/src/util`, and `core/src/api/firestore_bridge.cc`,
which is new. The Swift layer differs more because of the bridge to the C++
core; [Docs/UpstreamPatches.md](Docs/UpstreamPatches.md) lists the
differences.

**FirebaseDataEncoder: unchanged upstream.** Upstream hasn't touched it in
any compared release; the port's copy has local changes.

**FirebaseFunctions and FirebaseStorage: synced to 13.1.1.** Both were ported
from 12.16.0 and have since been synced; the checklists in
[Docs/upstream](Docs/upstream) record what was ported and what doesn't apply.
Storage scores low overall because its networking was rewritten:
`SessionFetcher` replaces GTMSessionFetcher, and has no upstream counterpart.

**FirebaseAuth: core synced to 13.1.1; iOS-only and multi-factor work pending.**
Upstream Auth became Swift in 11.0.0. The port's core (`Auth`, `User`,
`SecureTokenService`, `AuthBackend`, providers) was ported from 11.0–11.5 and
its RPC requests from upstream `main`, so *Synced to* stays at 11.0.0 while
work remains. Every upstream change since then is triaged in
[Docs/upstream/FirebaseAuth.md](Docs/upstream/FirebaseAuth.md): the core
fixes are ported, and the open items are iOS-only code (phone auth, APNs,
reCAPTCHA, the OAuth web UI, Game Center), multi-factor auth (which is
iOS-only, phone-only and without TOTP here), and the `AuthProviderID` enum.
The RPC types were rewritten as `Codable`, so their scores are low and say
little on their own; `--files --module Auth` gives the per-file view.

**FirebaseDatabase: synced to 13.1.1.** It was ported from about 11.2–11.8.1
(low confidence: upstream's Objective-C Database rarely changes, so most files
are the same in every release), and every upstream change since 11.2.0 has
been triaged. Its *Closest releases* stay meaningless for the same reason.

## The version the SDK reports

`FirebaseVersion()` (FirebaseCore) and `firebaseVersion` (Package.swift) are
**12.14.0**, the oldest baseline among Functions, Storage and Auth's RPC
layer. They're sent to the backends in version headers. Raise them when the
modules have been synced past it.

## Syncing a module

1. List what changed upstream since the module's *Synced to* release:

   ```sh
   scripts/upstream/changes-since.py Functions --output Docs/upstream/FirebaseFunctions.md
   ```

   The checklist has the module's CHANGELOG entries for the releases in
   between, and every upstream commit that touched its sources, with a guess
   at whether it's a fix, a feature or maintenance. `--to main` includes
   unreleased changes. The checklists in [Docs/upstream](Docs/upstream) are
   the current ones; the script won't overwrite one with ticked-off items
   unless you pass `--force`.
2. Triage each item: port it (with a regression test where feasible), or
   tick it off with a note on why it doesn't apply, such as Objective-C-only
   API or code this port replaced.
3. For vendored code (Firestore), apply the upstream diff instead of porting
   commit by commit:

   ```sh
   scripts/upstream/changes-since.py Firestore --patch firestore.patch
   git apply --reject firestore.patch
   ```

   Then resolve the `.rej` files and re-apply the local patches in
   [Docs/UpstreamPatches.md](Docs/UpstreamPatches.md).
4. Raise `synced_to` in `scripts/upstream/upstream.py`, run
   `scripts/upstream/baselines.py --write UPSTREAM.md`, and raise
   `FirebaseVersion()` and `firebaseVersion` once every module is past it.
